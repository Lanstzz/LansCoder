## 需要你自己搭的部分(gap)

1. **wiki 应用层**:没有页面模型/索引/模板/版本历史。用 `write/edit/apply_patch` 维护 markdown 页面即可,但这层逻辑(目录、链接、frontmatter)要你写。
2. **RAG/语义检索**:全仓 grep 不到 embedding/vector 支持;记忆是"名称+描述"级关键词索引。要做语义检索 wiki,需要自定义工具 + 外部向量库(chroma/faiss 等),或退而求其次用 `grep/glob` 做文本检索。
3. **自进化外层循环**:没有 scheduler/cron/自动触发。你要写"定时/事件触发 → web_search 收集新信息 → 评估旧页面是否过时 → 更新 → 写回记忆 → 收敛判断"的外循环。好消息是 L1 事件流可订阅、L2 有 `steer/follow_up/abort`,足以支撑这个外循环;坏消息是驱动逻辑(何时跑、跑多久、怎么判定"进化成功")没有现成件。
4. **web_search 依赖外部 key**:parallel/exa MCP,需 `EXA_API_KEY` 等,网络受限时要自行代理。

## 建议的搭建路径

- 最小可行:**L3 `create_agent_session` + 自定义 wiki 工具集(查询/更新/链接修复)+ 现有 memory 工具做长期事实记忆 + 自己写一个 `while` 外循环**——今天就能跑。
- 要更强:外挂 RAG(自定义工具),用 `delegate` 子代理并行做页面评审/重写,用 `tool_event_handler` 审计每次"进化"。
- 若你认为"向量检索/调度"应该是 SDK 原生能力而不是应用层,那可以作为一个新任务提案(目前公开面 20 个名字是被契约锁死的,新增属 minor/major 变更,需走 `.ai-team/TASK.md` 流程)。

一句话:harness 已经就绪,缺的是 wiki 和"自我进化"这两层应用逻辑——它们用现有 SDK 就能实现,不需要等 SDK 升级。
