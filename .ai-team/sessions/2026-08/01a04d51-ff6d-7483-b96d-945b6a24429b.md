## 2) LansCoder 目前的 L1/L2 机制

代码在 `lanscoder/context/compaction.py`、`tool_lifecycle.py`、`archive.py`。

**触发**(`triggers.py`):只看 token 水位 —— `input_tokens ≥ high_watermark`(可用容量的 90%)触发,压缩目标是 `low_watermark`(72%)。input_tokens 是 lanscoder 自己的 chars/4 估算(含系统提示/工具 schema/历史)。

**生命周期分类**(只对 `tool_result` 部件):
- `fresh`:`view`/`read_multi` 刚读的源文件 → 保留
- `derived`:普通工具输出(默认)
- `stale`:被 write/edit/delete 改过的旧读取 → 可归档
- `superseded`:被后续读取覆盖 → 可归档
- `duplicate`:内容重复 → 可归档
另外有"已消费"标记(模型已经看过该结果)。

**L1 — 路由压缩**:
- 只处理 **derived + 已消费 + 非检索保护 + 未压缩过** 的 tool_result。
- `RouteCompactRouter` 按内容类型选压缩器(JSON / HTML / build 输出 / git diff / 搜索结果 / 源码 / 纯文本),用 `cold_preview_chars=160` 生成"冷预览"替换原文。
- 原文存进 `ToolResultArchive`(archive_id + sha256),只替换"变小"的部件(`_replace_if_smaller`)。目标是:大而冷的输出 → 保留结构线索的小预览。

**L2 — 归档占位**:
- 候选两类:生命周期 **duplicate/superseded/stale 的强制归档** + **derived 且超过 per_result_target(默认 1200 tokens)的单结果压力**。
- 校验已消费 + 非检索保护后,`make_placeholder` 把原文替换成 ≤480 字符占位符,例如:
  ```
  [Tool result archived]
  archive_id=ar_xxx
  tool=file_system_read_file  lifecycle=stale  original_tokens=15234
  summary=...
  Use retrieve_archive(archive_id, ...) to inspect the original.
  ```
- 归档优先级 duplicate > superseded > stale > 超限,按序压到低于目标。

**流水线**:L1 路由压缩 → L2 归档占位;每层后估算,低于 target 且无剩余强制/压力候选就停(`stopped_at` 记下停在哪层)。L1+L2 不够才走 L3 LLM 摘要(checkpoint),L3 失败再更强规则压 → 硬截断。
