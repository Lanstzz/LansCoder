### 2. `--dangerously-skip-permissions` 的语义（重点）
- **语义 = 跳过权限提示**，不是"去掉所有限制"。
- 即使在 bypass 下，仍有**永不自动放行**的东西：显式 ask 规则的匹配项、`AskUserQuestion` 这类交互工具、命中关键路径的 `rm`、跨会话消息保护。

- 需要显式开启：`allowDangerouslySkipPermissions` 设置或 `--allow-dangerously-skip-permissions`，否则不让进；还提供 `disableBypassPermissionsMode` 彻底禁用。

- 文档原文：*"Always run `--dangerously-skip-permissions` sessions inside a container, a VM, or the sandbox runtime"*——bypass 会话**必须**在隔离边界里跑，且单独一个 Bash 沙箱还不够（文件工具/MCP/hooks 也要在边界内）。来源：[sandbox-environments](https://code.claude.com/docs/en/sandbox-environments)

- 两层隔离：**文件系统层 + 网络层**，独立开关。macOS 用系统内置 **Seatbelt**，Linux/WSL2 用 **bubblewrap**（文件系统）+ **socat**（网络代理）。

## 逃生门（escape hatch）是什么

**要解决的问题**：沙箱默认禁网 + 只能写项目目录后，会有一批**合法**命令跑不了——`pip install`、`git fetch/push`、`npm install`、`poetry install`，或写 `~/.kube` 这类工具依赖的目录。如果沙箱是"死禁"的，agent 遇到这些任务就卡死，用户只能整体关掉沙箱（更糟）。

**Claude Code 的做法**（[sandboxing 文档](https://code.claude.com/docs/en/sandboxing)）：
1. 命令触犯沙箱边界时，**不直接失败**，而是在结果里回报"被沙箱拦了，拦的是哪个 host/路径"；
2. 模型可以带 `dangerouslyDisableSandbox: true` 重试这一条命令；
3. 这条重试**跑在沙箱外**（全网络、全宿主权限），但**回到常规权限流程**——Manual 模式会弹确认，auto 模式过分类器。也就是说：**逃生门本身不是免确认通道**，它只是"单条命令离开沙箱"的开关；
4. 有 `allowUnsandboxedCommands: false` 配置可以**彻底关掉逃生门**（strict 模式），此时参数被忽略，所有命令必须留在沙箱内。

**关键设计意图**：注入提示词不能悄悄用逃生门——因为它一旦触发就**必须过人工/分类器这一关**。逃生门把"沙箱太严导致卡死"和"免确认裸奔"两个极端用一条带闸的门连接起来。

1. **审批层与沙箱层彻底解耦**（对齐 Claude Code）：权限模式只决定"要不要弹确认"；沙箱策略决定"命令实际能碰到什么"。进入 BYPASS 不等于解除沙箱。

3. **项目配置不能放宽沙箱**（对齐 Claude：项目 settings 不能关文件系统隔离）：恶意仓库里的 `lanscoder.toml` 不能把 `network=allow` 打开。放宽只能来自全局配置或 CLI。
4. **默认收敛、逃生有门、门后有闸**：默认禁网 + 项目内执行；确有合法联网需求走逃生门，但逃生那一下回到审批流。

## 1. 核心模型：两层正交

```
┌─ 审批层（已有，微调）──────────────────────────────┐
│  standard / aggressive / bypass                     │
│  bypass = 跳过确认（对标 --dangerously-skip-permissions）│
│  但 deny 规则 / 关键路径 / 交互工具 在任何模式都生效      │
└───────────────────────────────────────────────────┘
┌─ 沙箱层（新增，会话级不可变）────────────────────────┐
│  network: deny(默认) | allow                        │
│  resource: RLIMIT_CPU / NPROC / NOFILE / AS(可选)   │
│  filesystem: 子进程写限制（v1 起 macOS，Linux 视成本）  │
│  逃生门: dangerously_disable_sandbox → 回审批流        │
└───────────────────────────────────────────────────┘
```

- **不动的部分**：`SandboxAccess`（PROJECT/UNRESTRICTED）继续管**文件工具的路径参数**——standard=PROJECT，bypass=UNRESTRICTED，这是"everything"语义，保持现状。
- **动的部分**：`permission.py:_sync_sandbox_access_with_mode` 不再在 BYPASS 里设置 `network: allow` 和改写 sandbox 策略；模式切换只影响审批，不影响沙箱。

## 2. P0-1 执行沙箱

### 2.1 网络策略（默认 deny）
| 平台 | 实现 | 备注 |
|---|---|---|
| macOS | `sandbox-exec -p '(version 1)(allow default)(deny network*)'` 包裹子进程 | 系统内置 Seatbelt，无需安装；`sandbox-exec` 已弃用但可用（风险见待决策 #2） |
| Linux/WSL2 | `bwrap --unshare-net`（缺省则 `unshare -n`） | 依赖 bubblewrap，缺装时降级 |
| Windows | 不支持 OS 级禁网（对齐 Claude：Windows 走 WSL2 或容器） | 降级 + 告警 |

- 禁网时同时剥离 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 等代理 env（已有敏感 env 剥离逻辑可复用）。
- 全局开关：`--allow-network` / 全局配置 `[sandbox] network = "allow"`。

### 2.2 资源限制（rlimit，preexec_fn 应用）
- 默认开：`RLIMIT_CPU`（如 300s）、`RLIMIT_NPROC`（如 64）、`RLIMIT_NOFILE`（如 256）。
- 默认关：`RLIMIT_AS`（内存），避免误伤 node/编译器大构建；留配置项。
- 全部可在全局配置调整。

### 2.3 逃生门（已定：进第一批，默认 true）
- `shell`/`python_exec` 增加参数 `dangerously_disable_sandbox: bool = False`。
- `True` → 该条命令无沙箱执行，但**回到标准审批流**：有审批环境就弹确认，headless（`-p`/`--benchmark`）直接拒绝（对齐 Claude）。
- `[sandbox] allow_unsandboxed = false` → strict 模式，参数被忽略。
- 沙箱拦下时结果里报"被拦原因"（哪个 host/路径），让模型知道并可选逃生。

### 2.4 沙箱不可用时的行为
- 默认：告警 + 降级无沙箱执行（对齐 Claude 默认，避免用户卡死）。
- `[sandbox] fail_if_unavailable = true` → 硬失败（托管/安全门禁场景）。

### 2.5 逃生门之外调用点（git/worktree/grep/diagnostics）
- 这些走 `run_command` 的**结构化**调用点（git 固定子命令、grep 只读）v1 **不进沙箱**——否则 `git fetch/push` 在禁网下直接断。
- 风险敞口记录在案：git 子命令参数由模型生成，理论可注入 `--upload-pack` 等；v1 接受，后续可给 git 加白名单模式（`git fetch/push` 走网络策略）。

## 4. 配置面

```toml
[sandbox]
network = "deny"            # deny|allow（仅全局配置可放宽）
allow_unsandboxed = true    # 逃生门（仅全局配置可关=strict）
fail_if_unavailable = false # 沙箱起不来时是否硬失败
max_cpu_seconds = 300
max_processes = 64
max_open_files = 256
max_memory_mb = 0           # 0=不限

[permissions]
disable_bypass = false
bypass_confirmation = true
hidden_tools_extra = []     # 追加隐藏工具
hidden_tools_exempt = []    # 从默认隐藏集豁免
```

CLI：`--allow-network`（会话级）、`--permission-mode bypass`（显式进入，等价 `--dangerously-skip-permissions`）。
